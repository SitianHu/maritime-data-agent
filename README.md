# 航运智能问数

一个面向海事业务的轻量级本地智能问数应用。系统支持上传 CSV / Excel 数据，结合业务术语和数值编码字典理解自然语言问题，自动完成数据表路由、SQLite SQL 生成、安全校验、只读查询和可追溯答案生成。

## 主要功能

### 自然语言问数

- 自动识别问题意图、业务对象、统计指标和候选数据表
- 支持手动指定数据表，也支持系统自动路由
- 检索数据集关联术语，为 SQL 生成补充业务定义和统计口径
- 对信息不足或数据表不明确的问题返回补充条件提示，不盲目执行查询
- 使用稳定 SQL 规则约束同类问题的字段、筛选、聚合和分组方式

### 可追溯回答

- 回答默认突出“直接结论”和“结果明细”
- “统计范围、统计口径、可追溯信息和注意事项”统一收纳在折叠区域
- 展示 SQL 生成依据、实际 SQL 和原始查询结果，便于人工核验
- 记录识别意图、查询路线、使用数据表、数据更新时间和追溯编号
- 展示总耗时、SQL 生成耗时、数据库查询耗时、答案生成耗时和 Token 用量

### 数据表管理

- 支持上传 CSV、XLSX 和 XLS，单个文件最大 50 MB
- CSV 支持 UTF-8 / UTF-8 BOM，并兼容 GB18030 编码
- 自动清理空行、规范重复字段名并识别 SQLite 字段类型
- 支持数据表预览、显示名称重命名、删除和数据集隔离；重命名不会修改底层 SQLite 表名
- 问数查询返回 SQL 命中的全部结果，不设置固定行数上限；数据表预览仍最多显示 200 行

### 多表查询

- 先进行普通意图和主事实表识别，再通过规则评分补充问题所需的关联表
- 关联字段仅允许使用 `target_id`、`mmsi`、`imo`、`event_uuid` 的受控组合
- 评分综合考虑数据集术语、字段名称、表用途和实时属性关键词，不限制关联表数量
- SQL 生成只接收筛选后的表、字段和 JOIN 计划，最终还会执行表白名单安全校验
- 事件表之间优先先按关联键聚合，再连接聚合结果；仅提供筛选条件的关联表优先使用 `EXISTS`，避免连接造成重复计数
- 当前查询链路使用内置的受控字段组合生成 JOIN 计划，不会让模型自行猜测字段关系

### 业务术语库

- 新增、编辑、搜索和删除业务术语
- 支持同义词以及全局/指定数据集关联
- 支持通过 Excel 批量导入、导出术语；导出的文件可再次导入
- 术语定义会参与数据表路由、意图识别和 SQL 生成
- 问数时使用术语名/同义词关键词匹配与本地向量语义检索合并召回，不再用用户整句做 LIKE
- 默认嵌入模型为 Hugging Face `BAAI/bge-small-zh-v1.5`，通过 FastEmbed/ONNX 本地运行并将向量缓存到 SQLite
- 模型不可用时自动回退关键词检索，并在追溯信息记录实际检索方式

### 业务数值映射

业务数值映射用于解决“数据库保存编码、用户使用中文名称”的问题。例如，用户询问“货船”，系统可以将其转换为数据库中的真实船型编码进行筛选，并在结果中重新显示为“货船”。

- 通过 Excel 导入和校验编码字典，字段要求为 `dict_type`、`dict_code`、`name_cn`
- 支持编码字典版本管理与启用版本切换
- 支持新增、修改、删除编码项以及维护同义词
- 将数据表字段绑定到 `AIS_SHIP_TYPE`、`NAV_STATUS`、`RISK_LEVEL_CODE` 等编码类型
- 生成 SQL 时只允许使用字典提供的真实编码，禁止模型猜测编码
- 查询完成后自动将编码值翻译为业务中文名称
- 未找到映射的结果保留原始值，并写入可追溯警告

### 模型与会话

- 支持 OpenAI、DeepSeek、通义千问及其他兼容 OpenAI Chat Completions 的接口
- 支持在页面中测试模型连接
- API Key 和模型配置保存在当前浏览器的本地存储中，关闭页面或浏览器后仍会保留；服务端不持久化
- 支持创建、切换、重命名和删除本地对话
- 对相同上下文的 SQL 生成结果使用进程内缓存；缓存命中时 SQL 生成消耗为 0 Token，答案生成 Token 仍会正常统计

## 问数处理流程

```text
用户问题
  → 识别意图与数据表
  → 第二阶段按规则评分补全关联表并生成受控 JOIN 计划
  → 检索业务术语和数值编码映射
  → 生成 SQLite SQL
  → SQL 安全校验与编码筛选校验
  → 只读执行查询
  → 将结果编码翻译为业务名称
  → 生成自然语言答案与追溯记录
```

## 快速开始

建议使用 Python 3.10 或更高版本。

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

启动后访问：

- 应用首页：<http://127.0.0.1:8000>
- API 文档：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/api/health>

## 首次使用

1. 在“数据表”中上传 CSV 或 Excel 文件，并确认字段和预览数据。
2. 在“术语库”中补充业务术语、同义词和统计口径。
3. 如需跨表问数，直接描述涉及的业务条件；系统会在主表识别后补充相关表。
4. 可在数据表页面查看系统使用的受控关联字段和表用途规则。
5. 如数据包含枚举编码，在“业务数值映射”中导入编码字典并绑定对应字段。
6. 在“模型设置”中填写 API Base URL、模型名称和 API Key，并测试连接。
7. 回到“问数助手”，使用自动选表，或手动指定主数据表后开始提问；跨表所需的其他数据表仍由系统按规则补充。

## 术语库 Excel 格式

术语库支持 XLSX / XLS，导入文件最大 10 MB。首行必须包含以下字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `术语` | 是 | 术语名称，最长 100 个字符 |
| `定义` | 是 | 业务含义或统计口径，最长 1000 个字符 |
| `同义词` | 否 | 别名，最长 500 个字符 |
| `关联数据表` | 否 | 填写系统中的数据表显示名称；留空、`全局` 或 `全局术语` 表示全局适用 |

相同“术语 + 关联数据表”的记录会跳过；其余格式或数据错误会返回具体 Excel 行号。页面中的“批量导出”会生成同结构的工作簿，方便备份和迁移。

## 编码字典格式

编码字典支持 XLSX / XLS，文件最大 10 MB。每个工作表必须包含以下字段：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `dict_type` | 编码类型 | `AIS_SHIP_TYPE` |
| `dict_code` | 数据库真实编码 | `70` |
| `name_cn` | 中文业务名称 | `货船` |

导入前可先执行校验预览。系统会检查必填字段、空值以及同一编码类型下的重复编码。导入成功后会创建新版本并默认启用，已有版本数据仍会保留。

## 安全说明

- 后端仅接受单条 `SELECT` 或 `WITH ... SELECT` 查询。
- 拦截 `INSERT`、`UPDATE`、`DELETE`、建表、删表、`PRAGMA`、`ATTACH` 等操作。
- SQL 只能访问当前路由到的数据集表，不能跨数据集查询。
- 多表 SQL 只能访问第二阶段选中的表，并必须使用 JOIN 计划中的受控等值字段；禁止 CROSS JOIN。
- 数据库连接开启 SQLite 只读查询模式。
- 编码字段筛选会进行二次校验，防止模型使用未配置或错误的业务编码。
- API Key 会保存在当前浏览器的本地存储中，并仅随问数请求临时发送给模型服务；不会写入应用数据库或应用日志。请勿在不受信任或多人共用的浏览器中启用生产密钥。
- 当前项目未实现业务数值映射后台的用户鉴权；部署到生产环境前应增加身份认证、权限控制和 HTTPS。

## 使用说明

- 回答由大模型基于查询结果生成，重要数据请结合 SQL 和原始结果核验。
- Token 数取决于模型服务是否在响应的 `usage` 字段中提供用量；系统不会用估算值冒充实际用量。
- SQL 缓存保存在当前服务进程内，服务重启后会清空。
- 当前版本不生成图表。
- 问数结果不设行数上限，大数据量查询会增加服务端内存、接口响应体和模型上下文消耗；生产环境建议通过统计、分页或明确筛选条件控制结果规模。
- 可通过 `TERM_EMBEDDING_MODEL`、`TERM_RETRIEVAL_TOP_K`、`TERM_SEMANTIC_THRESHOLD` 和 `TERM_SEMANTIC_ENABLED` 调整术语语义检索；首次语义检索需要联网下载模型。
